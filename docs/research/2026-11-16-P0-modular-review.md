# P0 方案审查补充：可学习模块化协调（待批准）

日期：2026-11-16
状态：**修改建议，尚未获批准，未实现或实验**。
依据：[P0 设计 v0](2026-11-16-P0-design-v0.md)。

## 问题

用户指出：学习稀疏神经连接并不足以直观看到是否出现运动协调组织。是否采用显式模块化更容易学习和验证运动协调？

## 判断

**建议采用可学习模块化网络作为 P0 主方案，保留原先可学习稀疏连接方案作为对照，不推翻 P0 的结构化输入、分层闭环和任务设置。**

理由：
- 稀疏连接变化可反映优化/压缩，而不必产生可解释功能群落。
- 模块容器便于追踪激活、功能复用和定向干预。
- 但「模块边界预设」仍是归纳偏置；**模块化架构不保证功能分工，更不保证运动协同**。功能必须由实验验证。

## 具体主方案

1. 固定一个较小的**模块容量上限** K（具体值在实现设计时才选），每个模块具有自己的动态隐状态和可训练参数，**不赋予加速、刹车、跟车等语义**。
2. 高层根据结构化场景及反馈输出协调信号；可学习路由器根据当前状态选择/软激活模块。
3. 各模块接收运动状态反馈，独立更新动态状态，并通过**可学习的有限通信**交换信息。
4. 一个共享控制输出头整合模块状态，产生车辆连续控制；不将各模块的裸转向/制动命令直接线性平均。
5. 初期使用软路由以保障可微训练；是否加入稀疏激活/负载均衡，应在观察模块塌缩情况后单点确定，不提前堆损失。

示意：

```text
structured perception + navigation + execution feedback
                        |
                     high N
                        v
          learned router / interactions
               /       |       \
             M1  <---> M2  <---> M3   (K illustrative, semantics unknown)
               \       |       /
                 shared control head
                        |
                 vehicle + feedback
```

**学习得到的结构：** 模块功能、模块参与条件、模块间通信权重与活动动力学。
**人为规定的容器：** 总容量、初始模块数量上限、反馈通路、模块可通信的接口。此方案不宣称从无到有学出最优模块数量。

## 核心对照（控制容量、数据、反馈和训练预算）

- A: 单体循环策略（无明确模块划分）。
- B: 原 P0 可学习稀疏连接策略（动态连接，训练后寻找功能群落）。
- C: **可学习模块化策略**（模块容器 + 学习路由/通信）。

若要严格区分「模块容器」与「可学习协调路由」的贡献，另加 C0：同模块容器、固定均匀路由/无可学习通信。只在 C 表现有希望时追加此消融。

## 最关键的证据

- **分化：** 模块活动/路由条件出现非平凡差异；排除某模块长期不用、所有模块完全同质等塌缩情况。
- **复用：** 同一模块的功能效果在不同道路、交通条件下保留；不要求模块对应人类语义词，也不要求训练种子间编号一致。
- **因果协同与补偿：** 干扰模块或模块间通信，衡量任务相关变量误差与恢复时间；观察未受干扰部分是否重新组织，并比较参数量/损伤强度匹配的随机干预、单体策略及无通信消融。仅有活动变化或模块删除掉分不是充分证明。
- **有效性：** 同等训练与推理预算下提升闭环安全性、完成率或扰动恢复能力。若 C 不优于 A/B，则不能主张模块化必要。

研究依据：
- Goyal et al., *Recurrent Independent Mechanisms*, ICLR 2021: https://mlanthology.org/iclr/2021/goyal2021iclr-recurrent/
- Yang et al., *Multi-Task Reinforcement Learning with Soft Modularization*, NeurIPS 2020: https://papers.neurips.cc/paper_files/paper/2020/hash/32cfdce9631d8c7906e8e9d6e68b514b-Abstract.html
- Béna & Goodman, *Dynamics of specialization in neural modules under resource constraints*, Nature Communications 2025: https://pmc.ncbi.nlm.nih.gov/articles/PMC11695987/

## 2026-11-16 附录：模块之间如何协调？（仅供审查）

用户提出：肌肉在共同运动中既有拮抗也有协同，DLS 的多模块网络不能只是几个独立控制器再平均其动作。

**生物类比边界**：肌肉通过共同骨骼/关节等力学系统耦合；神经回路可实施共同激活、相互抑制和感觉反馈。计算模型中的「模块」更接近神经协调子回路，而不是独立肌肉。肌肉不直接输出油门/转向。参考：
- https://pubmed.ncbi.nlm.nih.gov/36309879/ （拮抗肌、共同激活）
- https://journals.physiology.org/doi/full/10.1152/jn.00084.2018 （肌肉共同激活与拮抗）
- https://pmc.ncbi.nlm.nih.gov/articles/PMC4350235/ （神经协调与身体力学耦合）

**候选方案**：模块保有动态内部状态 `h_i`，在每个低层 tick 接收车辆最新状态 `s_t`、高层条件 `z_k`、以及其他模块的可学习信息：
```
h_i(t+1) = f_i(h_i(t), s_t, z_k, Σ_j A_ij(t) P_j(h_j(t)))
u_t = D(h_1(t+1), ..., h_K(t+1))
s_(t+1) = F_env(s_t,u_t)
```
- `A_ij(t)`：可训练、可随状态变化的相互作用，数值可表达增强、抑制或无交互；不先行指定「转向模块」等语义。
- `P_j`：信息投影；`D`：共享输出解码器，不要求每个模块单独提供完整的油门/转向控制。
- 反馈同时通过共享物理状态和可学习的模块间通信传递。
- **该模型是待审查假设，不是生物神经回路真实实现的证据**。

为了避免过度复杂，建议先对比「只有共享物理反馈（A=0）」与「额外学习模块间通信（A 可学习）」；两组保持参数、数据、训练和输出接口尽量一致。这可直接检验神经间通信是否真的带来功能，而不是预设必须存在。
功能判据是跨情境复用与受控扰动下的互补补偿，不是仅看 `A` 是否有非零连接或模块之间是否相关。

本附录尚未获得用户批准，不代表改动 P0 正式方案或开始实验。
