# DLS D3e — 使用原训练权重提取完全无跨步记忆的 C 控制器

日期：2026-11-17。事前方案 [D3e](2026-11-17-D3e-stateless-reactive-controller-plan.md)。正式运行 [GitHub Actions #44039281732](https://github.com/Kryponitee/drive-like-a-living-system/actions/runs/44039281732)，**SUCCESS**。

## 回答的科学问题

D3c：跨模块消息内容消融在 BC C seed42/43/44 有显著方向差异，事前“至少2/3显著退化”的强必要性判据未通过。D3d：每 tick 清零**快环GRU历史**也没有稳定损害。D3e 再去除慢环跨时刻保持的状态z，测试现有 C 权重是否能只根据每个tick的**当前259维原始观测**执行基本驾驶，而不是继续增加通信机制。

## 唯一干预

无重新训练、无新专家数据；每tick调用原 `C_actor.step(o_t, initial_state=(h=0,z=0), t=0)` 并丢弃所有输出隐藏状态，因此慢环条件z每tick均由当前观测重新计算而**不持有历史**；快环全部GRUCell每tick从0记忆开始；输出、解码器、所有原始权重都不变。这是从RNN结构中**提取了纯当前观测输入的静态函数**，并不是另外训练的无记忆MLP，因此不作为严格等容量模型基线。

冻结D1 C BC seed42/43/44，密度0.10，地图3，24个与D3c/D3d完全相同的场景32000..32023。只新增72条episode，并复用D3c原始模型和D3d“仅清零快环h但保留慢环z”的144条历史结果；所有模型checkpoint前后SHA256一致，完整流程SUCCESS。

## 证据解释及下一阶段的关键决策

- **不能用“模块分工/通信网络可训练”替代“模块功能性的证据”。** D3a至D3e系列显示，在现有 BC seed42/43/44、同地图和交通密度下，功能性通信和持久GRU状态都没有一致必要性，尽管模块容量、注意力和路由都存在。
- **这不是“记忆完全无意义”的定理。** 手动清零状态是OOD干预，且同一场景集用于逐项诊断；专家BC训练目标与环境可能不足以迫使记忆形成。seed44恰有一定记忆依赖，不能忽视。
- **不再盲目增加PPO步数、通道数或让模块学习人为标签。** 下一项高价值检验应是**重新训练一个与原C容量/数据/BC预算匹配的纯前馈控制器**。如果它在独立场景中能与C保持近似性能，则可进一步确立“当前监督目标/任务不要求循环功能”而不受清零OOD混淆；如明显落后，说明当前循环策略内仍有结构/记忆价值但消融方式不够细。
- 在容量匹配无记忆基线后，再根据需要调研官方MetaDrive可复现的部分观测、遮挡和动态交通场景，构造**真实时间信息需求**，不是为了人为制造“通信比无通信更强”的结果。每次只改变一个定义清楚的实验变量。
