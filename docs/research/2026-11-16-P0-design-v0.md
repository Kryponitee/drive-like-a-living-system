接续：[运动协调结构 v0](2026-11-16-structure-proposal-v0.md)（已获原则认可）、[感知接入规划](2026-11-16-perception-integration-v0.md)（P0/P1/P2 尚待整体审查）。

## 0. P0 唯一要回答的主问题

**在具有结构化环境观测的闭环驾驶中，允许神经网络学习内部连接，是否能形成可复用、具有反馈补偿功能的运动协调组织？**

P0 **不研究摄像头感知**，但仍提供状态化的环境信息；因此 P0 不是「没有感知」，也不是视觉端到端。不要将「网络内部可学习稀疏连接」直接等同于「运动协调结构」。

### 一点原则

本轮只改变一处：**协调系统 C 的循环连接是否允许数据驱动重组**。其余的观测、神经决策 N、控制输出、数据、目标、训练预算尽量一致。

## 1. 首选闭环仿真：MetaDrive（暂定，执行前确认安装/设备兼容）

理由：
- 可直接输入结构化状态，不依赖视觉编码器。
- 原生连续动作 `[steering, throttle_brake]`，每维范围 `[-1,1]`，第二维正值驱动、负值制动。
- 可程序化生成道路、交通及不同地图，支持训练与留出场景。
- 内置 `IDMPolicy` 和预训练 `ExpertPolicy`，可作为驾驶数据来源候选（**先检查实际专家质量与数据导出，不预设成功**）。
- 可扩展视觉输入，利于 P1 过渡；跨仿真器迁移不是 P0 的结论。

官方依据：
- https://metadrive-simulator.readthedocs.io/en/latest/obs.html
- https://metadrive-simulator.readthedocs.io/en/latest/action.html
- https://metadrive-simulator.readthedocs.io/en/latest/rl_environments.html
- https://metadrive-simulator.readthedocs.io/en/latest/training.html

为什么暂时不选 highway-env：内置不少决策任务默认给出离散高层动作，不利于直接检验低层连续控制组织。为什么暂不以 CARLA 为起点：它更适合后续逼真视觉/复杂交通验证，但 P0 需要低成本快速闭环迭代。这是研究工具选择，不是对仿真忠实度的排名。

## 2. 最小闭环系统：N（慢环）与 C（快环）

```text
结构化环境状态、导航、上次执行反馈
                |
                v
       神经决策 N（慢环）
                | z_k
                v
车辆实时状态 -> C（快环、有状态、可学习连接） -> 连续控制 a_t
      ^                                                   |
      +--------- MetaDrive 执行车辆动力学与交通演化 <-------+
```

- `N_theta`：共享的简易 MLP 或小网络，读取自车状态、路线、邻车/交通摘要和历史执行结果，生成连续条件 `z_k`；它**不输出轨迹**。
- `C_phi`：单个有状态循环网络，读取 `z_k`、实时局部运动状态、上一时刻动作，直接给出连续控制 `a_t`。
- 低层局部输入至少包括：速度、横摆角速度、车道横向偏差、当前局部前方间隙及相对速度（若有前车），上一动作。这些值在仿真 P0 中直接读取；P1 需要可观测的替代表示。
- 高层结构化输入包括：自车状态、短路线/道路几何、附近车辆的相对状态、导航意图及执行反馈。**禁止读未来真实轨迹、碰撞预测答案、仿真器内部决策策略或留出场景标签**。
- 频率暂按「低层每个控制 tick 更新，高层每 5 个控制 tick 更新」作为 *待调节工程初值*；不要擅自假定恰好对应某个 Hz。
- 控制输出使用 MetaDrive 原生 `a_t=[steer_t, throttle_brake_t]∈[-1,1]^2`；暂不添加另一个手工运动规划器来掩盖 C 的能力。
- 评价指标独立于训练 reward。安全干预若启用必须记录次数，且所有方法采用相同机制。

形式：
```math
z_k = N_theta(o_k, f_k)
h_{t+1} = sigma(W_x [s_t^{local}, z_k, a_{t-1}] + (M ⊙ W_h) h_t + b)
a_t = tanh(W_o h_{t+1})
s_{t+1} = F_env(s_t, a_t, ξ_t)
```

- `M` 是循环连接掩码；**不预设成多少肌肉/技能模块**。
- 同构 N 与 C 容量跨组一致；仅改变连接学习规则。
- `M` 训练后可固定，`h_t` 仍随反馈持续变化。

## 3. 学习什么：只比较连接是否可学习

主要两组：

| 组别 | C 内部连接 | 作用 |
| --- | --- | --- |
| Fixed Sparse | 固定随机稀疏连接，只学权重 | 主对照 |
| Learned Sparse | 稀疏连接在训练中删除和重建（候选：RigL 风格） | 核心方案 |

参考组：容量/计算可比的 Dense RNN，避免只证明稀疏化工程优势或大参数优势。稀疏两组必须匹配隐藏单元数、活跃连接数、初始化、数据和更新预算；额外的拓扑更新开销需要单独报告。学习稀疏连接本身**不保证**得到功能模块。

具体初始稀疏率、隐藏维度和增长/剪枝间隔，应以小规模可行性与开销审计再定；不盲设 K=8。

## 4. 教师数据与闭环训练（先给最小主流程）

- **D0 数据检查**：用 MetaDrive 内置 `ExpertPolicy` 或 `IDMPolicy` 采样不同道路/交通条件的连续 `(observation, action, next_state)`；先验证专家成功率、是否具备转弯/交互等覆盖，不把内置策略当作完美专家。
- **D1 离线行为克隆（BC）**：相同示范数据分别训练 Fixed Sparse / Learned Sparse，验证能否形成基础驾驶能力。这一步只能说明能模仿，不能说明协同。
- **D2 闭环训练**：在相同随机化环境与优化预算下，以基于任务反馈的交互优化进一步训练（候选：PPO；在正式代码设计时检查循环稀疏梯度实现与 RL 框架兼容性）。训练过程中动作改变后续观测。
- **D3 干预研究**：完成基础驾驶后，冻结参数进行结构与反馈测试；避免将「对动作噪声敏感」误当作协同功能。

如果内置教师数据覆盖不足，先补充场景/采样，不为满足流程硬做 BC；必要时改为直接闭环学习，但两组保持公平一致。

## 5. 场景：三组训练，两个变化维度

先选择覆盖纵横控制和交互的最小场景组合：

1. **道路跟踪**：直路、弯路、初速度变化。
2. **交通适应**：跟车、前车减速、合理制动与恢复。
3. **交互决策**：变道/汇入或交叉口让行（优先选择 MetaDrive 已支持且可稳定重置的场景）。

训练场景混合而不是分别训练单独的技能标签。

测试区分：
- **未见场景**：新地图、曲率、交通密度与初速度，按 map seed/scenario id 严格划分，避免重叠。
- **有控制的扰动**：前车提前/突然减速、初速变化、车辆动力学轻微偏差（仅选仿真可实现且所有模型一致的干预）。

初期先跑 3 个独立训练随机种子排除明显不稳定；如有有效趋势，再增至 5 个及置信区间。样本量是计划而非既定统计证据。

## 6. 读结果的三道关卡

### G1：会开车吗？

- 指标：闭环任务完成率、碰撞率、越界率、进度、运动控制平滑性。
- 如果 Learned Sparse 连基本驾驶能力都不具备，不进入结构涌现结论。
- 首先对比 Fixed Sparse / Learned Sparse / Dense，不夸大性能优势。

### G2：真的形成了可复用的内部组织吗？

- 分析训练前后网络的连接社区和状态共同活动的统计结构。**这些只是结构候选，不是协同证明**。
- 在不同任务/不同地图中观察候选组织是否扮演稳定的控制角色；不强制不同种子对齐神经元编号。
- 对某个结构候选进行**度数/规模/权重范数匹配**的局部破坏，与同强度随机破坏比较，量化对控制和驾驶任务的影响；若无差异不能声称功能分化。

### G3：是不是有反馈补偿，而不是纯粹相关？

- 相同受控扰动后观察任务相关误差/恢复时间、内部激活变化。
- 比较正常反馈、临时延迟/屏蔽底层反馈、局部结构干预等；必须控制输入信息缺失对所有模型造成的普通影响。
- 若 C 的某部分受干预，其他内部成分是否能进行**超出对照预期的**功能补偿？
- 只有「结构候选 + 跨场景复用 + 因果干预 + 功能补偿」才支持协调主张；不能因模块化或稀疏就称 synergy。

### 主要失败分支（预先保留）

- Learned Sparse ≈ Fixed Sparse：没有证据表明动态连接学习提供增益。
- Learned Sparse 好但无稳定功能组织：可能只是更好的优化或容量使用。
- 发现内部群落但没有任务影响：仅能报告结构模式。
- 干预有影响但普通 RNN 同样具有恢复性：不能把一般闭环能力单独包装成运动协同。

## 7. 研究边界与审查内容

不做：
- 不上视觉、ViT、BEV，也不称视觉端到端；
- 不预先命名「加速」「转向」「刹车」神经元；
- 不同时加入多个生物启发机制和手工协调损失；
- 不只凭效果提升/连接图漂亮宣称协同。

**本轮唯一需审查的设计选择：是否以 MetaDrive + 双时间尺度 N/C + 固定稀疏 vs 学习稀疏（同控制目标）作为 P0 主线？**

未获审查前，不写训练代码、不选择规模超参、不运行实验。
