# Drive Like a Living System — P0 可执行研究方案 v1.0

**日期**：2026-11-16  
**状态**：P0 研究方案已整理（模块化协调与模块间通信为研究主线）；**尚未开发或进行实验，工程参数需 D0 核验**。  
**研究边界**：P0 只采用结构化状态作为感知输入，研究神经运动协调；不进行视觉端到端训练。  
**前序记录**：[原 P0 草案](2026-11-16-P0-design-v0.md) · [模块化审查](2026-11-16-P0-modular-review.md) · [感知路线 P0/P1/P2](2026-11-16-perception-integration-v0.md)。

## 0. 问题与最小假设

**P0 主问题**：一个由数据训练的模块化闭环控制网络，能否自发形成**可复用、具有反馈补偿作用的模块分工与交互机制**？

不把「网络分成模块」「出现注意力连接」或「驾驶分数更高」直接等同于运动协同。

**核心可证伪假设 H**：在训练数据、环境、模型容量和计算预算尽可能匹配的条件下，具有可学习**直接模块通信**的控制器，比仅通过共享车辆反馈协作的同构模块化控制器，更能在受控扰动下实现功能补偿与跨场景复用。

保持前一阶段原则：不预设「加速/制动/转向/跟车」模块的职责，也不要求学出的内部结构唯一。

## 1. 系统接口：高层 N 与低层 C

```text
路线 + 道路几何 + 邻车状态 + 自车状态 + 执行反馈
                       |
                       v
                  N_theta（慢环）
                       | z_k
                       v
自车及局部运动状态 -> C_phi（快环，K 个可学习模块）
                       | 控制 [steer, throttle_brake]
                       v
                 MetaDrive 车辆及交通
                       |
                       +------ 实时反馈 C_phi
                       +------ 聚合反馈 N_theta
```

- **环境**：优先 MetaDrive。采用其结构化观测；不能把未来真实轨迹、内部教师决策、未来碰撞标签作为策略输入。
- **慢环 N**：共享的轻量网络（初版 MLP），每隔 `q` 个环境控制步更新条件 `z_k`；其余时刻保持最近一次条件。
- **快环 C**：各模块每个控制步根据观测和自身记忆更新活动。模块语义不预设；内部控制器可先用 GRUCell 作为计算构件，而不是把它与真实生物肌肉等同。
- **物理反馈**：每个环境步获取可观测的速度、姿态/横摆、道路偏差、邻车相对状态及上一控制指令。环境反馈直接驱动 C，也被汇总供 N 使用。
- **输出**：MetaDrive 标准连续动作 `[steering, throttle_brake] ∈ [-1,1]^2`。正的第二维为驱动、负值为制动；各模块**不分别输出完整驾驶动作并加权平均**。
- **安全机制**：训练/测试中的安全覆盖如果启用，对所有模型一致；单独记录覆盖次数，不能将覆盖成功归因于协调网络。

### 1.1 C 的数学结构

以下描述一个**可实现的模型假设**，不是已经验证的神经科学对应。

设第 `i` 个模块的动态状态为 `h_{i,t} ∈ R^d`，输入 `x_t` 为局部状态，`z_k` 为高层条件。模块间通信为：

```math
m_{i,t} = \sum_{j\neq i} A_{ij,t} V_j h_{j,t},
```

```math
h_{i,t+1} = \operatorname{GRUCell}_i([x_t,z_k,m_{i,t}],h_{i,t}),
```

```math
\alpha_{i,t}=\operatorname{softmax}_i(r_\eta(z_k,x_t,h_{1:K,t})),
\qquad
\mu_t=\tanh\!\left(D_\omega\left(\sum_{i=1}^K \alpha_{i,t}P_i h_{i,t+1}\right)\right).
```

实际 PPO 训练时以 `mu_t` 为动作分布的受限均值，按适合连续动作边界的方式采样并计算正确的 log probability；评测阶段采用确定性动作。注意力 `A_ij` 可由模块状态和场景条件学习得到；即使注意力系数非负，经过可学习投影 `V_j` 也可产生不同方向的信号。**不能仅凭注意力符号断言兴奋/抑制的生物意义。**

- **B：只用物理反馈**：强制 `m_{i,t}=0`；保留同样的模块、路由及共享输出。**增加等预算的局部状态变换支路**（只允许读取本模块状态）作为容量匹配对照，避免 C 仅因多了通信参数获胜。
- **C：物理反馈 + 直接通信**：`m_{i,t}` 由可学习通信机制给出。
- **模块数 K 为容量上限**，而非预设生物肌肉数量或学出的真实单位数量。
- 可考虑让通信图随状态变化；初版不对注意力/路由施加人工技能标签，不同时加入多个结构正则损失。
- 计算顺序必须固定：先用 `h_t,x_t,z_k` 计算消息/路由，再同步更新各模块，并生成动作、读取下一状态，避免同一 tick 的因果循环。
- 初版保留软路由，不预先强制 top-k 激活；若发生所有模块同质化或长期闲置，再单独研究约束。

### 1.2 工程起始配置（可通过 D0 检查调整）

这些数字是**首轮工程初始化，不是科学结论**：
- `K=4` 个模块，各 `d=32` 维循环状态，`z=16` 维协调条件。
- N 为小型 MLP；控制更新每环境步一次，高层初始每 5 个控制步更新一次。
- 禁止人为分配模块职责；只给出总容量。
- 对 A（单体网络）调整隐藏宽度以尽量匹配 C 的**可训练参数数目和推理成本**；B/C 可用相同架构及容量预留通信参数，对增加的计算和参数进行单独审计。不可把 B/C 参数显著不等同的结果视为公平架构优势。
- 不在该设计阶段锁定具体学习率、奖励权重、更新次数与物理模拟频率；D0 先核验 MetaDrive 版本与时间步。

## 2. 环境、数据与训练

**训练情境至少涵盖三类**（混合训练，不给模型显式「技能 ID」）：
1. 道路跟踪：直道与不同曲率弯道。
2. 纵向交互：自由行驶、跟车、前车减速和恢复。
3. 交互路况：换道/汇入或无保护路口（选择一个 MetaDrive 可稳定重置、提供连续动作的场景，执行前确认）。

**输入/数据约束**：训练/测试按独立 map seeds 和 scenario seeds 分割，固定生成配置并记录环境版本、车辆动力学设置和随机种子。不得把测试地图混入离线专家数据。

分四个滚动里程碑：

| 阶段 | 具体动作 | 完成判据 |
| --- | --- | --- |
| D0 环境/数据审计 | 跑通 MetaDrive 连续控制、获取结构化状态；审查 `ExpertPolicy` / `IDMPolicy` 的任务覆盖及输出；确认可用的可重复扰动接口 | 可重置、可复现同一场景；不存在输入泄漏；教师有可用的连续控制记录 |
| D1 离线 BC | 使用同批专家示范训练 A/B/C；损失最小版本为控制动作的行为克隆，时序 hidden state 必须正确重置与截断 | 至少学出有意义的基本驾驶能力并记录失败场景；不声称结构涌现 |
| D2 闭环优化 | 统一优化预算下采用循环策略适配的 PPO（或经审查的等价交互优化），同样的奖励/交通条件；动作影响后续观测 | 三组都能在留出场景完成基础任务，再进入结构研究 |
| D3 结构与反馈干预 | 冻结策略，做模块/通信干预、不同状态扰动及 held-out 测试 | 给出对「分工、复用、补偿」的证据或否定结论 |

注意：MetaDrive 专家在不同场景的适用范围并不相同。若 D0 无可用示范，不强行进行 D1；记录偏差并改为直接闭环学习。必须三组公平使用同样数据/环境，不混用不同优化目标。

## 3. 对照和最小消融

| 代号 | 网络 | 能回答什么 |
| --- | --- | --- |
| **A** | 结构化状态 -> N -> 单体 RNN -> 控制 | 普通有反馈策略的能力上限/基线 |
| **B** | 同样的 N + K 个模块 + 软路由 + 共享输出；**无直接通信** | 仅靠共享车辆反馈是否已足够 |
| **C** | 与 B 相同，但启用**可学习模块间通信** | 直接神经模块交互的边际价值 |

- **主对照为 B vs C**；两组需要匹配有效参数量、训练环境步数与推理 FLOPs，并让 B 用仅依赖自身状态的额外变换支路匹配 C 通信层的容量，才能尽可能分离「跨模块信息传递」的因果贡献。
- A 用来判断显式模块化是否有必要。
- 原 RigL 动态稀疏结构学习记录作为**备选对照 D**，不在首轮主试验同时变更多个机制。
- 训练数据、观测字段、奖励、评测场景、随机种子、初始化尺度、训练环境步数需匹配；记录可训练参数量、实际算力成本与学习曲线。

## 4. 我们如何知道确实学出了「运动协调」？

采用三道关卡，不把结构外观当成结论。

### G1 能驾驶
官方/自定义场景的闭环成功率、碰撞、出界、完成进度及控制平滑度；先排查训练崩溃/行为退化。

### G2 模块分工与复用
- 记录逐时刻 `alpha_i`、模块活动 `h_i`、通信权重 `A_ij` 及任务状态。
- 观察是否存在非平凡分工：模块不是永远等权、单模块垄断或完全同质。
- 不能仅凭激活相关性宣称功能；对模块做一次短暂状态置零/信息屏蔽，比较与等规模、等能量的随机扰动，对控制目标的因果影响。
- 同一模块在新地图和不同初始速度下，若可产生**相近的任务层面的干预效果**，视为复用的证据之一。无需与人为「跟车模块」名称对应。

### G3 反馈补偿（主要机制）
- 在同一时刻给 B/C 同等的可恢复车辆扰动或短时间模块/通信干预；
- 记录损伤后的任务误差、恢复时间、路外/碰撞率、其余模块活动与路由重配；
- **关键不是「其它模块也有变化」，而是这些变化是否可因果地减轻任务损失**。
- 附加「屏蔽/延迟反馈」测试，区分真正利用闭环反馈与时间模式播放；同样的输入缺失/算力条件下比较所有模型。
- 主报告基于 paired scenario seeds 和多训练 seeds；先做 3 个训练种子的探索性试跑，再做至少 5 个训练种子及配对置信区间的确认性测量（样本数后续根据效应量与方差定）。

判定等级：
- **L0**：只学会驾驶——不能声称运动协调。
- **L1**：模块活动/通信出现差异——只是候选结构。
- **L2**：模块有可重复的功能角色和跨场景复用——存在功能性组织证据。
- **L3**：干预可引起可测、可解释的反馈补偿，并且 C 相对 B 改善关键任务变量——支持「有用的运动协调」的主张。

**主要否定结果**：
- C≈B 且成本更高：直接模块通信不必要。
- C 比 B 好但无稳定功能分工：更可能是容量或优化收益。
- 只能看到路由分化，没有复用或补偿：不可称协同机制。
- A 具有同等补偿与泛化：不能宣称模块结构独占这种能力。
- 模块损伤导致性能下降：仅说明重要性，不能单凭此证明协同。

## 5. 设计选择、工具与回退

- P0 仿真首选 MetaDrive；其默认 `LidarStateObservation` 包含自车状态、导航信息与周围环境特征；可按任务改为显式结构化向量。
- 车辆输出统一为两维连续动作；不在 C 后面再加入一个未说明的规划器。
- 先用 PyTorch 实现模块、路由、通信与隐藏状态管理；闭环 RL 依赖兼容循环隐藏状态的算法实现，`Stable-Baselines3` 普通 PPO 不能自动假定支持自定义 recurrent module；选工具时必须核查。
- 若第三类交互场景专家覆盖不足，优先保证前两类和一个已核验可控的交互场景，不凭空宣称全部具备。
- D0 数据/环境不可复现，停止后续训练；D1 三组均不能形成基本驾驶能力，先处理学习/教师覆盖而不加新结构；D2 不能稳定闭环，不进行协同证明；D3 无机制证据则如实报告。

## 6. 研究依据（支持范围）

- RIM (Goyal et al., ICLR 2021)：独立模块动力学、按需激活和有限通信的技术先例；不保证在驾驶中自然形成语义技能。https://mlanthology.org/iclr/2021/goyal2021iclr-recurrent/
- Soft Modularization (Yang et al., NeurIPS 2020)：任务相关软路由和模块复用；不提供 DLS 的分层闭环结论。https://proceedings.neurips.cc/paper/2020/hash/32cfdce9631d8c7906e8e9d6e68b514b-Abstract.html
- MetaDrive 文档（2026-11-16 核对）：状态观测、连续两维动作、专家策略及交互场景。https://metadrive-simulator.readthedocs.io/en/latest/obs.html ，https://metadrive-simulator.readthedocs.io/en/latest/action.html ，https://metadrive-simulator.readthedocs.io/en/latest/rl_environments.html
- 生物运动协同不是固定模块数或模块功能的证明；实验定义详见 [记录 001](2026-11-16-motor-coordination-definition.md)。
